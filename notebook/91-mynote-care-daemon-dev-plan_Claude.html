전제: [[90-mynote-care-daemon-plan_Claude]] — 채널 정체성·카테고리(5트랙 생성 완료)·콘텐츠 처분.

1. 목표 · 원칙

  • 품질 아주 좋게 — “돌봄 데몬” 채널의 기준작이 될 수준. 양보다 밀도.
  • 한 편씩 — 한 편마다 완결. 게이트 통과해야 다음 편으로.
  • 페어 발행 — 모든 편 = 티스토리 글 + GitHub Pages 페이지 한 쌍. 단일 원고(md) → 두 곳.
  • 돌봄 ≠ 소망 구분 — 여기엔 돌봄(길 1)만. 라디오·노래 AI 등 소망(길 2)은 S21.

2. 총 편수: 10편 (Season 1)

한 켠(카테고리)씩, 총 다섯 켠을 한 바퀴 도는 구성. 10편이면 “돌봄 데몬이 무엇인지”가
완결된 하나의 서사(매니페스토 → 제도 → 스토리 → 기술)로 닫힌다.

아크 구조:

[토대] 매니페스토 (1편)
   ↓
[제도] 트랙 DW·DC·BL (3편)  ← "무엇을 돌봐야 하는가"
   ↓
[스토리] 대화록 (1편)        ← "누구의 하루인가"
   ↓
[기술] 솔루션 (5편)          ← "어떻게 기술로 돌보는가" = 돌봄 데몬 본체

3. 편별 상세 (10편)

✅ 확정 카테고리 구조 (계층형, 2026-08-15 재구축 완료) — 아래 표의 “카테고리”는 이 트리를 따른다.

매니페스토 — 기술로 돌보는 법 (1307301) 트랙 — 제도 (1307302) ├ DW — 장애·정신건강 복지 (1307305) ├ DC — 치매·노인 돌봄 (1307306) └ BL — 기초생활 보장 (1307307) 대화록 — 하루 스토리 (1307303) 솔루션 — 돌봄 데몬 (1307304) ├ 아키텍처 (1307308) ├ 배터리·온도 (1307309) ├ 위치·GPS (1307310) ├ 원격 돌봄망 (1307311) └ 보고 무전기 (1307312)

# 제목(가제) 카테고리 원천 핵심
01 돌봄 데몬이란 — 기술로 돌보는 법 (매니페스토, 최상위) care/care.conf + 정체성 왜 “데몬”인가. AI 제로 독립, 15분 주기. 전체 지도
02 트랙 DW — 장애·정신건강 복지의 빈틈 트랙 DW tracks/disability-welfare.md 조현병 누나. 행정 창구 빈틈 + 원페이지 연계맵
03 트랙 DC — 치매·노인 돌봄의 빈틈 트랙 DC tracks/dementia-care.md 치매 어머니. 하루 타임라인 + 확인 창구
04 트랙 BL — 기초생활 보장의 빈틈 트랙 BL tracks/basic-livelihood.md 기초생활 가구. 갱신·신고 체크리스트
05 대화록 001 — 하루가 시작되기 전 대화록 dialogue/2026-07-26-opening.md 오프닝. Scene/Feel/Gap/Fix/Next 구조 첫 사례
06 솔루션 01 — 돌봄 데몬 아키텍처 솔루션 care/care-daemon.sh crontab */15. state.json. 모듈 분해도
07 솔루션 02 — 배터리·온도 감시 솔루션 care-daemon.sh (배터리/온도) 급감 30%/60분, 저전압 15%, 과열 45°C
08 솔루션 03 — 위치·GPS 돌봄 솔루션 care-daemon.sh (GPS) 무응답 2h, 무변동 6h, 반경 500m 이탈
09 솔루션 04 — 원격 돌봄망 (Tailscale) 솔루션 care/tailscale- + start-.sh 원격 접속·상태 재연결. 방화벽 없이 안전망
10 솔루션 05 — 보고 무전기 (텔레그램) 솔루션 care/tg.sh 1차(헬레나)→2차(목사님) 에스컬레이션

4. 품질 기준 (편마다 통과해야 할 게이트)

  1. 한 편 = 하나의 질문 + 하나의 답 — 제목이 곧 그 편의 질문.
  2. 실물 원천 인용 — 스크립트/설정 실제 값을 인용(임계값 15%/45°C/500m 등). 추상 금지.
  3. 비단정 표현 — 법령·의료는 “확인 창구 / 확인일”로. (helana_log 규칙 계승)
  4. 민감정보 차단 — 실 GPS·주소·진료 원문·토큰 절대 금지. (헌법: 돌봄 데이터 공개 금지)
  5. 페어 동기화 — 티스토리 본문과 GitHub Pages 페이지가 같은 원고에서 나온다.

5. 페어 발행 파이프라인

원고(md, 단일 원천)
   ├─→ [티스토리] post.py → mynote11605 카테고리 발행   (URL 불변)
   └─→ [GitHub Pages] helana_log docs/*.html 빌드       (coverage 게이트)
  • 티스토리 = 업무일지/발행처, GitHub Pages = 원자재 창고+웹 전시 ([[reverse-publishing-pattern]]).
  • 원고 위치: 돌봄 데몬 콘텐츠는 helana_log/docs/ 하위(트랙/대화록/솔루션)에 두고, 티스토리 발행은 helena_phone 파이프라인이 가져간다.

6. 실행 순서 (한 편씩)

  • [ ] Step 0 — 원고 규격 확정: 템플릿 1개(트랙/솔루션/대화록 각각) + 품질 게이트 스크립트.
  • [ ] Step 1 — 01 매니페스토: 채널 선언 + 10편 지도. 이게 나머지 9편의 목차.
  • [ ] Step 2 — 02~04 트랙 3종: 기존 tracks md를 “품질 게이트” 수준으로 재작성.
  • [ ] Step 3 — 05 대화록: 오프닝 스토리 한 편.
  • [ ] Step 4 — 06~10 솔루션 5종: 돌봄 데몬을 모듈별로 해설.
  • [ ] Step 5 — 페어 검증: 매 편 티스토리 + Pages 동시 확인 후 커밋.
