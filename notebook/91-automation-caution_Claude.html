GUI 자동화 주의사항 — “사람 손가락”처럼 보인다는 착각 (2026-08-14)

한 줄: 티스토리 자동발행은 된다. 단, 그건 “안 들켜서”가 아니라 티스토리가 관대해서다. 같은 코드를 네이버·인스타로 옮기면 바로 걸린다.

1. 가장 중요한 오해 하나

“터목스 폰 IP로 CLI 조정하니까, 웹에서 들어가는 거랑 달리 사람 손가락 클릭이랑 구분 못 한다” — 반은 맞고, 반은 틀리다.

  • ✅ 맞는 반: 폰의 한국 이동통신 IP는 “어디서 들어왔나”(지리·평판) 축에서 유리. 네이버의 해외 IP 차단은 진짜로 피할 수 있다.
  • ❌ 틀린 반: IP는 “사람인지 봇인지”를 판단하지 않는다. 그 판단은 브라우저 안에서 일어난다.

2. 탐지는 두 축으로 나뉜다

축 뭘 보나 우리 상태
IP 축 (어디서) 지리·ISP·평판 ✅ 폰 이동통신 IP → 유리
브라우저 축 (누가) JS 지문·행동 ❌ headless Chromium → 표적

두 축은 독립적이다. IP가 아무리 사람 같아도, 브라우저가 봇이면 걸린다.

3. 브라우저 축이 봇을 잡는 방법 (지문)

신호 사람 폰 지금 우리(Playwright headless)
navigator.webdriver undefined true ← 적발 1순위
User-Agent 모바일 Chrome HeadlessChrome 표식
화면·뷰포트 360~430px 폰 1280×900 데스크톱
터치 이벤트 있음 없음
navigator.plugins 실제 플러그인 빈 배열
행동 타이밍 불규칙·지연 기계적·일정

→ 지금 post.py는 headless=True 데스크톱 크롬이라 “사람 손가락”과 정반대 모습이다. 구분 못 하는 게 아니라 구분하기 제일 쉬운 모습이다.

4. “사람처럼” 보이려면 (하지만 하지 말 것)

기술적으로는 가능하다:
- headless 끄기(Termux:X11) → --disable-blink-features=AutomationControlled → stealth 패치 → 모바일 UA/뷰포트 → 터치 → 사람 같은 지연.

하지만 그 지점부터는 명백한 “탐지 회피(evasion)”다. “내 콘텐츠 자동발행”에서 “플랫폼 우회 공격”으로 성격이 바뀐다. 교재로 가르치지 않는다.

5. 그래서 진짜 결론

  • 티스토리가 통과되는 이유 = 카카오가 관대 (Open API 유산 + 저강도 단속). “우리가 안 들켜서”가 아니다.
  • 네이버 = 캡차·2FA·보안로그인 → 브라우저 축에서 바로 막힘.
  • 인스타(메타) = 자동화 전면전 → 계정 밴. 확장 금지.

6. 지키는 선

구분 기준
✅ 허용 내 콘텐츠 · 사람 속도(1일 10개 미만) · 공식 API 우선 · 플랫폼이 관대한 곳
❌ 금지 스팸·대량·가짜 활동 · 탐지 회피(stealth) · 타인 콘텐츠 무단 · 인스타

7. 교재화 방향

  • 기술만 가르치면 “우회 따라하기”, 판단(ToS·윤리·플랫폼별 온도)을 같이 가르치면 커리큘럼.
  • 챕터: 공식 API vs GUI 차이 → 탐지 2축(IP/브라우저) → 플랫폼별 한도 → “내 콘텐츠 vs 악용”의 선.

8. 우리 파이프라인 위치

  • 현재 = 티스토리 + 내 콘텐츠 + 저빈도 → 실사용 무해.
  • 확장 = 네이버·인스타 GUI 자동화는 여기서 선을 긋는다.

9. Boss 확정 (2026-08-14)

“네이버·인스타는 나중에 수익화할 수 있는 플랫폼이다. 싫어하는 자동화를 하면서까지 뚫을 필요 없다. 거기는 수작업 전용 — AI가 못 하는 것만 사람이 직접 한다.”

  • 탐지 리스크(앞 절)와는 별개인, 전략적 이유로도 자동화를 안 한다.
  • 수익화 플랫폼에서 손맛·미적 판단·발행 버튼은 사람의 몫 = 브랜드 그 자체.
  • AI의 자리는 원고 생성·자산 준비·포맷팅(업스트림)까지. 마지막 발행은 사람 손.
