0. Claude에게 시킨 것 (복기)

Grok 퀼트 패키지 확인 + 도전?
→ 네이버 PC 관리 화면이면 클릭/콘솔로 다 될 것 같다
→ Playwright로 좌표 찍으면 파이썬 자동화
→ 모바일 GUI는 나중에 APK 손가락
→ 카테고리 관리 등 손으로는 너무 어려움 (드래그 안 됨)
→ 커뮤니티 리서치

Claude 답 (e4b9886 / 중복 §91):

  • Tistory ≠ Naver (KOE006 없음, ID 로그인 가능)
  • 1회성 admin 설정은 Playwright 가치 있음
  • 주간 발행은 Paste Pipeline 유지
  • “좌표 클릭으로 해결 가능” ← 여기가 과함

1. 판정 한 줄

영역 판정 이유
주간 본문 발행 풀오토 ❌ 비권장 SE ONE·품질·정책·퀼트 브랜드 붕괴
1회성 카테고리 추가 ⚠️ 반쪽 가능 쿠키 세션 + locator (좌표 X)
카테고리 드래그 정렬 ⚠️ 매우 어려움 DnD·지연 반영 (공식 안내: 글 많으면 시간 소요)
글쓰기 시 카테고리 선택 ✅ 이미 코드 있음 post.py select#categoryId
쿠키 기반 글쓰기 봇 ⚠️ 기술 가능, 운영 위험 커뮤니티에 사례 다수 · ncaptcha·계정 리스크
스킨 CSS / 서식 ✅ 손 1회 Marine Quilt 정본
MetaWeblog 글쓰기 API ⚠️ 레거시 계정별 활성 여부 확인 필요 · 관리 카테고리 생성 API 아님

2. Claude가 맞은 것

  1. Tistory와 전선이 다르다 — Kakao OAuth / KOE006 지옥이 아님.
  2. 1회성 설정 vs 매주 발행 분리 — Boss 판단과 일치, 브랜드(퀼트)와도 일치.
  3. 모바일 카테고리 UI는 지옥 — 공식도 PC 경로 위주. 드래그 정렬은 폰에서 사실상 포기 수준.

3. Claude가 틀린/위험한 것

주장 교정
“좌표 찍어서 자동화” 절대 좌표 금지. 해상도·배율·A/B UI에 즉시 깨짐. get_by_role / get_by_text("카테고리 추가")
“DOM 안정적” 관리자·SE는 자주 바뀜. locator + 재녹화가 정석
“ID+PW만 있으면 된다” ncaptcha 있음. 레포 NAVER_WORKBOOK도 RustDesk로 사람 캡차 우회 설계
풀 GUI = 모든 관리 가능 DnD 정렬·주제분류 팝업·2단 구조는 실패율 높음

4. 쓰레기통에서 건진 방법 (우선순위)

A. 사람 1회 로그인 → storageState (최강 반쪽)

headed Chrome/Playwright
  → 네이버 로그인 (캡차는 사람)
  → storageState 저장 (login.cjs 이미 있음)
  → 이후 headless/headed 재사용
  • 이미 있음: tistory-naver/login.cjs, post.cjs, post.py
  • 매일 비번 자동 입력 ❌ → 쿠키 수명 끝날 때만 사람 재로그인

B. 카테고리 “추가” 1회 스크립트 (권장 도전 범위)

PC 경로 (공식 고객센터):

관리 → 메뉴·글·동영상 관리 → 메뉴 관리 → 블로그
→ [카테고리 추가] → 이름·공개·주제분류 → 저장

Playwright 전략 (좌표 아님):

  1. 저장된 쿠키로 admin URL 진입
  2. get_by_text("카테고리 추가") 클릭
  3. 이름 입력 필드 fill
  4. 확인/저장
  5. 스크린샷 + 실패 시 TG 알림 → 사람이 이어서

드래그로 2단/순서 는 1차 범위에서 제외. 사람은 5분, 봇은 이틀 삽질.

C. 네트워크 가로채기 (있으면 잭팟)

카테고리 추가 한 번 수동으로 하면서 DevTools Network 캡처:

  • XHR에 category / menulist 류 요청 있으면
  • 같은 쿠키로 fetch 재현 → UI 클릭 불필요
  • 없으면 B로 후퇴

D. 글 발행 시 카테고리만 지정 (이미 있음)

tistory-naver/post.py:

select#categoryId / select[name='categoryId']
→ select_option(label=cat)

카테고리 이름만 미리 사람/1회봇이 만들어 두면, 이후 글봇·또는 손발행에서 선택만 하면 됨.

E. MetaWeblog / 글쓰기 API (레거시 확인 과제)

  • 관리 → 글쓰기 API 설정 → 암호 발급
  • 외부 툴 newPost 시 기본 카테고리 프리셋 가능 (문서상)
  • 카테고리 목록 생성 용이 아님
  • 2026년 계정별로 막혀 있을 수 있음 → helena1975에서 1회 프로브만

F. 주간 퀼트 발행 (정본 유지)

TG 패키지 → 서식 불러오기 → 손 붙여넣기 → 발행

여기 Playwright 넣는 순간 수공예 퀼트 브랜드 자살.
기술적으로 가능해도 전략적으로 안 함.

G. 상업 “슈퍼봇” / 멤버십 매크로

  • 커뮤니티에 많음
  • 계정 제재·스팸 지수·브랜드 오염
  • 쓰레기통에 도로 넣음

5. 권장 아키텍처 (3층)

8. 최종 답 (Boss 질문)

방법 없는 매제 찾아봐

  • 완전 무방법 아님.
  • 매주 풀오토는 방법 있어도 안 한다 (퀼트·정책).
  • 1회 카테고리 시드는 방법 있음: 쿠키 + locator (+ 가능하면 XHR).
  • 좌표·비번 무한 재시도·상업봇 = 쓰레기.
  • Claude 방향(1회 admin / 매주 paste)은 전략적으로 맞고, 전술(“좌표”)만 고쳐라.
