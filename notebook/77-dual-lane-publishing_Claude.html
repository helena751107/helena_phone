듀얼레인 출판 원칙 — GitHub Pages(영문·PWA 앱) × Tistory(한글·인터랙티브)

Boss 결정 (2026-09-29)
기록 agent: _Claude
근거: 75-translation-logic-management_Claude.md(출판부 7규칙)을 언어·형식 축에서 확장.
이 문서는 출판부 7규칙의 규칙 1(로컬원장=SSOT)을 대체하지 않고, 그 위에 언어·형식 레인을 추가로 얹는다.

1. Boss 선언 (원문 취지)

“GitHub Pages는 영문으로 쓸데없이 글을 쓰는 게 아니라, 무조건 앱의 형태 — 버튼 인터랙티브한 앱의 형태로 만들어야 한다. 한글로 된 인터랙티브한 페이지는 Tistory로 만든다. 웹페이지를 배포·출판할 때는 반드시 두 레인 — Tistory 한글판 + GitHub Pages 영문판 — 을 동시 출판하는 걸 원칙으로 한다.”

2. 현재 상태 대비 (2026-09-29 점검 결과)

실제 코드 점검 결과, 지금까지는 정반대로 되어 있었음:

위치 지금까지의 실제 상태 새 원칙
GitHub Pages (index.html, 5레포 전부) lang="ko", 한글 아코디언 웹진(webzine.js) 영문 + 인터랙티브 앱(PWA, 버튼)
README.md (GitHub 저장소 첫 화면) 영문 그대로 영문 유지 (변경 대상 아님 — Pages가 아니라 저장소 랜딩)
Tistory 사람이 수동 복붙하는 Paste Pipeline 크로스포스트 (독립 인터랙티브 아님) 한글 인터랙티브 페이지의 1차 발행처

Boss 확인: “예, 영문으로 전환 (원칙 그대로)” — 기존 5레포 GitHub Pages를 한글→영문으로 뒤집는 것까지 포함해 승인됨.

3. 새 원칙 (확정)

  1. GitHub Pages = 영문 · 인터랙티브 앱(PWA) 레인.
    - 평문 스크롤 아님. 버튼·토글·탭 등 상호작용 요소가 있는 앱 형태.
    - site.webmanifest의 lang을 en으로, index.html의 <html lang="en">으로.
    - 기존 webzine.js(검색·접기·펼치기·복사)는 인터랙션 뼈대로 재사용 가능 — 언어만 영문 콘텐츠로 교체.
  2. Tistory = 한글 · 인터랙티브 레인.
    - 지금의 “사람이 복붙” 수동 파이프라인에서, 한글 콘텐츠의 1차 발행처로 격상.
    - Tistory 플랫폼 한계 안에서 가능한 인터랙션(펼침 글상자, 목차 링크 등) 활용.
  3. 동시 출판 원칙 (필수).
    - 새 웹페이지를 배포·출판할 때 Tistory 한글판과 GitHub Pages 영문판을 동시에 낸다.
    - 하나만 나가고 하나가 누락된 상태로 “출판 완료”라고 보고하지 않는다.
  4. SSOT 관계 (출판부 규칙 1과의 정합).
    - 로컬원장(_notebook/*.md, 한글)이 여전히 원본. Tistory 한글판은 이 원본을 가깝게 따른다.
    - GitHub Pages 영문판은 번역본이자 별도 포맷(앱 UI) — 기계적 1:1 변환이 아니라, 앱 UI에 맞게 재구성된 영문 콘텐츠.

4. 실행 스코프 (5레포 전체 재작업 — 대형 작업)

5개 레포 GitHub Pages를 전부 한글→영문+PWA 앱으로 뒤집는 건 콘텐츠 재작성 규모가 크다 (레포당 index.html + 하위 notebook 페이지 다수). 파일럿 우선순위:

순서 레포 사유
1 helena_phone 헤드쿼터(리그1 허브) — 가장 먼저 기준을 세워야 나머지가 따라감
2 helana_log 리그1, Boss 운영 — 기술 로그라 영문 전환 상대적으로 쉬움
3~5 helena-piano / helena-metalcare / helana-faith 리그2, 누나 명의 — 콘텐츠 톤 민감 (신원 비공개 등 각 레포 가드레일 준수 필요)

5. 출판부 7규칙과의 관계

  • 규칙 1(로컬원장=SSOT) — 유지. 단, “로컬원장 → 웹페이지”가 이제 1:1이 아니라 1:2(한글 Tistory + 영문 GH Pages).
  • 규칙 5(품질등급 standard 이상) — 영문판에도 동일 적용, 단 “표준 템플릿”은 인터랙티브 앱 UI 기준으로 별도 정의 필요(추후 76-page-writing-standard_Claude.md에 영문 앱 UI 섹션 추가 예정).
  • 규칙 7(metrics 주간 보고) — 듀얼레인 커버리지(Tistory 발행 여부 + GH Pages 영문 발행 여부)를 metrics에 추가해야 함(추후 publishing_metrics.py 확장 필요).
