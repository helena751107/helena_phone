# 🛡️ 돌봄 마스터 설정 — Helena S21 (Galaxy S21)

**버전**: v1.0 (2026-08-24) | **위치**: `care/CARE-MASTER.md` (helena_phone 레포) + PC 미러 `~/dtslib-localpc/helena-care-master/`
**원칙**: *돌봄 = "누나의 삶에서 매일 뭘 확인하고, 그 확인이 뭘 바꾸는가"* — 기기 지표가 아니라 삶의 결과로 정의한다.

---

## 0. 왜 이 문서인가

누나의 S21은 단순한 폰이 아니라 **돌봄 공장의 검증 라인**이자, **누나의 몸에 붙어 있는 유일한 상시 센서**다.
배터리 2%/hr, swap 77% 같은 건 **라인 유지비**일 뿐이다. 이 문서는 그 라인이 실제로 만들어내는 **산출(케어 결과)**을 정의한다.

**핵심 판정**: 지금까지의 ADB 플랫폼은 "폰의 건강"을 체크했다. 돌봄으로 전환하려면 체크 대상을 **"누나의 삶의 신호"**로 올려야 한다.

## 2. 돌봄 역할 → 슬롯 지도

역할(직무기술서)을 정의하면 태스크가 나오고, 태스크마다 슬롯(앱/스크립트)이 정해진다.

| 역할 | 담당 대상 | 슬롯 (태스크) | 트랙 |
|------|----------|--------------|------|
| **간병인** (신체·일상) | 누나 본인 | ① 복약 알림+확인 ② 식사 체크 ③ 이동/귀가 안전 ④ 이상 징후 | 2 / 1 |
| **요양사** (장기·인지) | 어머니(치매) | ⑤ 어머니 복약·병원 일정 추적 → 누나 알림 (부담 경감) ⑥ 인지 활동 리마인더 | 2 |
| **심리치료사** (정서·정신) | 누나 (조현병) | ⑦ 정서 체크인 ⑧ 말로 하는 대화 (LLM) ⑨ 위기 감지 → 에스컬레이션 | 2 / 1 |

> **안전선**: LLM은 "치료"를 대체하지 못한다. 정서 슬롯은 **체크인 + 지지 + 위기 조기발견**까지만.
> 위기 시엔 **사람(박씨/전문가)으로 넘긴다.** 슬롯 이름은 "심리치료사"가 아니라 **"정서 지원팀"** 으로.

## 3. 3-tier 빌드 규칙

```
태스크 정의 → 슬롯 설계
  tier 1: 오픈소스 앱 있음      → 그대로 가져온다 (원가 0원)
  tier 2: 삼성/구글 앱이 이미 함 → ADB로 조종·데이터 연동 (원가 0원)
  tier 3: 없음                  → proot에서 자체 구축 (유일한 실제 개발)
```

### 태스크 → OSS/기존 자산 매핑

| 태스크 | OSS/기존 자산 | tier |
|--------|--------------|------|
| 복약 알림 | **MedTimer** (F-Droid OSS) 또는 Termux cron+알림 | 1 |
| 정서 체크인 | Telegram 봇 + Claude/DeepSeek (LLM이 상담일지 자동작성) | 3 |
| 귀가/이동 안전 | **OwnTracks**·**Traccar** (OSS GPS) | 1 |
| 기분/습관 | **Habitica** (OSS) | 1 |
| 화면시간/과사용 | **삼성 디지털 웰빙** (이미 폰에 있음) | 2 |
| 활동/수면 | **삼성 헬스 + Google Health Connect** (공개 API) | 2 |
| 원격 돌봄 관리 | **Google Family Link** (구글의 돌봄 앱) | 2 |
| 배터리/발열/GPS 감시 | **care-daemon.sh** (이미 구축됨, 트랙 1) | 1 |
| 위기 감지(미접촉) | care-daemon 확장 + watchdog | 3 |
| 케어 일지 | `건강검진표/` 폴더 자동화 | 3 |

> **구글·삼성이 이미 "돌봄 앱"을 만들었다**: Family Link, Digital Wellbeing, Samsung Health, Health Connect.
> 우리의 일은 "만드는 것"이 아니라 **ADB/인텐트로 조종해서 슬롯에 꽂는 것**.

## 4. ADB 조종 규칙 (뚫기 vs 편집)

**원칙**: *"뚫어서 편집"이 아니라 "조종 + 데이터 연동"* — 삼성/구글 앱은 그대로 두고 ADB가 리모컨이 된다.

| 할 수 있는 것 | 못 하는 것 (루트 없음) |
|--------------|----------------------|
| `am start` → 앱/화면 강제 실행 | APK 내부 코드 수정 |
| `pm enable/disable` → 앱 켜기/끄기 | 타 앱 private 데이터 직접 읽기 |
| `settings put` → 볼륨/애니메이션 등 조작 | 시스템 영역 쓰기 |
| `input tap/text` → UI 자동화 | — |
| `dumpsys` → 배터리/GPS/알림/센서 읽기 | — |
| `pm grant` → 권한 부여 | — |

## 5. 슬롯 뼈대 (모든 슬롯 공통 구조)

```
트리거 (언제)  →  시간 기반 / GPS 기반 / 미접촉 기반
행동   (뭘)    →  텔레그램으로 물어보기 / 알림 / 기록
판정   (그래서) →  정상 / 주의 / 위기 → 위기면 박씨·목사님에게 에스컬레이션
```

**예 — 복약 슬롯**:
```
트리거: 매일 20:00
행동: "오늘 저녁 약 드셨어요?" → 누나 "응" 입력
판정: 응=기록 / 무응답 1시간 뒤 재확인 / 2회 무응답 → 박씨 텔레그램 "⚠️ 복약 미확인"
```

## 6. 트랙 구조

### 🟢 트랙 1 — 물리 안전 감시 (기존, 확정)
- **care-daemon.sh** (Termux 네이티브, proot 밖) — 15분마다 실행
- 체크: 배터리 저전압(15%) · 급감(30%/60분) · 과열(45°C) · GPS 무응답(2h) · 위치 무변동(6h)
- 알림: 텔레그램 → **헬레나(1차) → 목사님(2차 에스컬레이션)**
- 설정: `care/care.conf` / 설치: `care/care-setup.sh`

### 🟡 트랙 2 — 복약 + 정서 지원 (설계, 빌드 예정)
- 복약 슬롯: 알림 + 확인 + 무응답 에스컬레이션
- 정서 체크인: 매일 아침 텔레그램 "컨디션 어때?" → 답변 기록 누적 → 주간 경향 리포트
- 어머니 케어 일정 추적: 병원/약 일정을 누나 대신 추적 → 알림 (누나 부담 경감)

### 🔵 트랙 3 — 케어 일지 자동화 (설계)
- `건강검진표/` 폴더를 "기기 검진"에서 **"케어 일지"**로 확장
- 모든 트랙의 결과가 날짜별로 자동 합산 → 주간 리포트 자동 생성

## 7. 표준원가 · 가동 조건 · 통과 기준

### 표준원가 (건강검진표 2026-08-24 실측)
| 항목 | 기준값 | 근거 |
|------|--------|------|
| 라인 대기 소모율 | **~2%/hr** | 100→95% / 2.5h 실측 |
| 순수 폰 대비 프리미엄 | +1~1.5%/hr | 라인 대기 유지비 |
| 대기 가능 시간 | ~47h | 2%/hr 기준 |
| 검증 실행원가 | **미측정** | 작업별 배터리 % 기록 필요 |

### 가동 조건 (초안 — 미확정)
```
라인 대기 표준원가 = 2%/hr          ← 확정
가동 조건 = 충전 중 + 배터리 ≥ 80% 에서만 검증 실행
실사용 보호 = 09~22시 검증 워크로드 스톱
검증 실행원가 = 다음 실행부터 작업당 배터리 % 기록
```

### 통과 기준 (초안 — 라인 결과를 근거로 만들기)
```
- "S21에서 돌아감" 판정 기준 = Exynos 2100 / 8GB / Android 15 하한
- TTS 1건 ≤ 300MB RSS / PD 렌더 1건 ≤ 배터리 2%  ← 이후 실측으로 고도화
- 검증 결과는 건강검진표/날짜/ 폴더에 raw 포함 저장
```

## 10. 돌봄 원칙 (변경 금지)

1. **체크 결과의 1차 소비자는 누나 본인** — 데이터가 먼저 누나에게 가고, 이상 있을 때만 개입.
2. **누나가 끌 수 있는 슬롯** — 돌봄은 계약이지 점검이 아니다.
3. **AI는 치료를 대체하지 못한다** — 정서 지원 + 위기 조기발견까지만, 위기는 사람으로.
4. **의료 단정 표현 금지** — "확인 필요"로 돌린다.
5. **인프라는 공유한다** — 이 마스터는 오픈소스로 뿌려도 되는 재료다.
