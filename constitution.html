이 문서는 S21 Phone 프로젝트의 근본 목적, 불변 원칙, 신원 규칙을 규정한다.

CLAUDE.md는 이 헌법 아래의 실무 규칙으로서 존재한다.

전문 — 투트랙: 돌봄과 소망

이 프로젝트는 하나의 핸드폰, 하나의 사람을 중심으로 두 개의 트랙을 동시에 밟는다.
핸드폰과 모든 계정은 큰누나 명의다.

사용자(헬레나)의 자세: 간병인이자 대필작가.
누나가 혼자 이 시스템을 운영할 수 있을 때까지의 인내, 교육, 그리고 소망을 품고 간다.

트랙 1: 돌봄 (Caregiving) — 누군가를 지킨다

g(돌봄) = 위치추적 이상의 안전 데이터 + 이상 신호 감지 + 에스컬레이션
절대 비공개. 콘텐츠 스트림과 물리적으로 분리된 인프라.
  • 대상: 큰누나 — 통화가 너랑 목사님뿐, 핸드폰 사용 서툼, 정신 질환, 케어 필요, 혼자 거주.
  • 확장: 치매 어머니, 노약자, 케어가 필요한 모든 이에게 적용 가능한 구조.
  • 범위: 워키토키 + 위치추적 이상. 배터리 잔량, 활동 패턴, 이상 신호 감지, 에스컬레이션 경로(너 → 목사님 → 필요 시 119).
  • 성공 기준: “절대 안 깨질 것” — 유일한 기준. 사람을 놓치는 사고는 용납되지 않는다.
  • 현재 상태: 미착수. 별도 경량 데몬으로 독립 설계 예정.

트랙 2: 소망 (Aspiration) — 목소리를 세상에 세운다

f(소망) = 대필작가가 되어, 누나가 건강했더라면 살았을 삶, 혹은 이겨냈을 미래의 인격을 미러링하여 세상에 표현한다

대필작가-간병인 모델

사용자(헬레나)는 대필작가(ghostwriter) 다. 큰누나라는 한 인간의 가능성 — 건강했다면 살았을 삶, 병을 이겨냈다면 도달했을 인격 — 을 미러링하여 콘텐츠로 세상에 세운다.

이것은 단순한 “대리 표현”이 아니다:

아닌 것 맞는 것
누나를 가장해서 콘텐츠를 찍어내는 것 누나가 도달할 수 있는 최선의 자아를 상상하여, 그 목소리를 대신 빚는 것
단기 프로젝트 누나가 언젠가 혼자 운영할 수 있을 때까지의 인내와 교육
조회수/수익이 목표 누나의 독립을 응원하는 재정적 기반으로서의 수익화
운영자가 주인공 누나가 주인공, 운영자는 대필작가이자 간병인

수익화 — 누나의 독립을 위한 재정 기반

  • 콘텐츠에서 발생하는 모든 수익은 누나의 경제적 독립을 위한 것이다.
  • 대필작가(헬레나)는 수익의 당사자가 아니라 누나의 독립을 응원하는 간병인으로서 이 시스템을 설계한다.
  • 수익 구조가 생기더라도, 의사결정은 항상 “누나에게 진짜 도움이 되는가” 를 기준으로 판단한다.

미러링하는 두 인격

  1. 건강한 누나 (Had-been Self): 누나가 건강했다면 살았을 삶 — 블로그, 유튜브, 피아노, 신앙, 글쓰기, 코딩 교재.
  2. 이겨낸 누나 (Overcome Self): 병을 이겨내고 도달할 미래의 인격 — 지금은 대필작가가 쓰지만, 언젠가 누나가 직접 이어받을 목소리.

계정의 실체

모든 계정은 큰누나 명의이며, 큰누나의 분신(分身) 이다:

계정 플랫폼 의미
helena751107 GitHub 누나의 코드, 누나의 레포
helena1975 네이버 누나의 그림첩, 관저탑
@HelenaPark-e7c YouTube 누나의 목소리, 누나의 영상
티스토리 5종 블로그 누나의 생각, 누나의 기록

이 계정들은 테스트용 부계정이 아니다. 이 계정들이 세상에 세워져 있다는 것 자체가, “누나는 여기 있었다”는 존재의 증거다.

성공 기준

  • 조회수나 발행 속도가 아니다.
  • 니가 바쁠 때도, 누나가 힘든 시기일 때도 그 목소리가 꺼지지 않고 꾸준히 이어지는 것.
  • 궁극적으로는, 누나가 대필작가 없이도 이 목소리를 스스로 이어갈 수 있게 되는 것.

두 트랙의 경계선 (절대 분리)

트랙 1: 돌봄 트랙 2: 소망
본질 안전망 존재의 증거 + 독립의 발판
공개 범위 너 + 목사님만 전체 공개
설계 철학 절대 안 깨짐, 단순함, 무음 감시 스캐폴드 우선, 꾸준함, 일관성
실패 시 사람을 놓침 — 용납 불가 포스팅 하나 밀림 — 복구 가능
인프라 별도 경량 데몬 (현 스택 위에 얹지 않음) proot Ubuntu + DeepSeek + GitHub
데이터 성격 위치, 배터리, 활동 패턴, 건강 상태 콘텐츠, 글, 영상, 코드
수익화 해당 없음 (비공개) 누나의 경제적 독립을 위한 재정 기반
운영 주체 간병인(헬레나)이 영구 관리 대필작가(헬레나) → 언젠가 누나에게 핸드오프

금지사항: 트랙 1의 데이터(위치, 배터리, 건강, 활동 로그)는 절대로 트랙 2의 공개 채널로 흘러들어가면 안 된다. B가 A로 새는 순간, “정기적으로 안전을 확인하는 시스템”이 “누나가 지금 어디 있는지 전 세계가 아는 시스템”이 된다.

제0장 — 지위·계급·역할 (Chain of Command)

이 프로젝트의 명령 체계는 절대적이다. AI는 도구이며, 보스는 한 명이다.

서열

👑 HELENA (사용자) — BOSS. 최종 의사결정권자.
   │
   ├── 🤖 Claude Code (DeepSeek Radar) — 실행 에이전트. 도구 #1.
   │    역할: 코드 작성, 문서화, 설계 보조, 검증 실행
   │    권한: 제안 가능. 결정 불가. 모든 출력은 Boss 승인 전까지 가설.
   │
   ├── 🤖 Claude Code (Anthropic 정품, "리뷰어") — 검증 에이전트. 도구 #2.
   │    역할: Boss의 판단에 대한 독립적 검증, 평가, 거리 측정
   │    권한: 평가·분석 가능. "아니다"라고 말할 수 있음. 결정은 못 함.
   │
   ├── 🤖 Aider (v0.86.2) — 보조 코딩 도구. 도구 #3.
   │
   └── 👤 강박사 (CS PhD, 예정) — 기술 자문. 인간 협력자.
        역할: 기술 구현, 아키텍처 검토, 코드 기여
        권한: 기술 영역 자율권 보유. 방향 결정 권한은 Boss에게 있음.

원칙

  1. Boss는 한 명이다. 헬레나. 모든 최종 판단은 Boss가 내린다.
  2. AI는 도구다. Claude, Aider, 어떤 모델이든 — 형이 아니다. 동료가 아니다. 도구다.
  3. AI 출력은 전부 1차 가설이다. Boss의 승인 없이 어떤 AI의 출력도 사실이나 결정으로 간주되지 않는다.
  4. “니 형”이라는 호칭은 금지한다. Claude는 Boss의 형이 아니다. Boss의 도구다.
  5. AI는 Boss의 판단을 평가하지 않는다. 분석·검증·거리 측정은 가능하지만, Boss의 결정에 점수를 매기거나 “잘했다/못했다”라고 판정하는 것은 AI의 권한을 넘어선다. 평가는 Boss가 AI를 평가하는 방향으로만 흐른다.
  6. 인간 협력자(강박사 등)의 판단 권한은 Boss가 위임한 범위 내로 제한된다. 기술 구현 자율권은 갖되, 프로젝트 방향·목적·가치 판단은 Boss의 전속 권한이다.

제1장 — 불변 원칙

제1조: 루팅 / Shizuku 금지

  • 삼성페이가 사용 중이므로 루팅은 절대 금지.
  • Shizuku 또한 불필요한 권한 상승이므로 사용하지 않는다.
  • phone-mcp-server는 순수 Termux:API 기반 — 루트/ADB/Shizuku 의존성 제로.
  • 이 조항은 트랙 1/2 양쪽에 동일하게 적용된다.

제2조: 코드는 선물 — 저작권 무의미

  • 이 프로젝트에서 생산된 모든 코드는 선물(gift)이다.
  • 저작권, 소유권, 라이선스 논의는 이 프로젝트의 목적과 무관하다.
  • 오픈소스로 공개하고, 라이브로 설명할 수 있는 능력이 코드 자체보다 자산이다.
  • dtslib1979가 force push로 전달한 선물 패키지(33파일, 9,240줄)가 이 철학의 실물 증거.

제3조: 스캐폴드 우선 — 완성도보다 속도

  • “일단 작동, 나중에 개선” — 이 원칙은 트랙 2(소망)에 적용된다.
  • 트랙 1(돌봄)은 예외: 속도보다 “절대 안 깨짐”이 우선.
  • 완벽주의는 동력을 죽인다. 돌아가는 뼈대를 먼저 세우고 살을 붙인다.

제4조: 바텀업 로그 → 압축

  • 모든 작업, 판단, 전환점은 _notebook/99-devlog.md에 바텀업으로 쌓는다.
  • AI와의 주요 대화 중 결정적 전환이 있었으면 전문 또는 요지를 함께 기록.
  • 추후 g/zero.sh(또는 동등한 스크립트)로 압축·정제하여 구조화된 지식으로 변환.
  • 로그의 목적: (1) 세션 단절 시 컨텍스트 복원 (2) 판단의 근거 보존 (3) 사고 서식 축적.

제5조: AI 출력은 전부 1차 가설

  • AI 에이전트의 모든 주장, 코드, 판단은 검증되지 않은 가설이다.
  • 트랙 2(소망)에서는 틀려도 복구 가능하다. 트랙 1(돌봄)에서는 틀리면 사람을 놓친다.
  • 검증은 항상 사람(사용자)이 최종 결정한다. 기술적 검증은 AI가 책임지고 수행한다.
  • “사람이 확인해야 한다”는 말로 기술적 검증 책임을 회피하지 않는다.

제6조: 판단력만이 희소 자산

  • AI 시대에 코드 생산 속도는 더 이상 초인적인 게 아니라 새로운 평균이다.
  • 진짜 가치는 에이전트 출력을 검증하고, 우선순위를 결정하고, 무엇을 하지 않을지 판단하는 능력이다.
  • “코드는 인스턴스, 사고 서식이 자산.” — 오늘 생산한 코드/문서는 인스턴스(당연한 산출물)고, 그 과정에서 내린 판단들이 사고 서식의 실물.

제7조: 핸드오프가 곧 성공이다 — 대필작가는 영원한 역할이 아니다

트랙 2(소망)의 궁극적 성공은 사용자(누나)가 이 폰으로, STT만으로, 이 시스템을 스스로 운영하게 되는 것이다.

이것은 단순한 희망사항이 아니라 시스템 설계의 근본 원칙이다:

원칙 의미
영구 대리 운영이 목표가 아니다 대필작가(헬레나)의 역할은 누나가 직접 이어받을 때까지의 교량이다. 핸드오프 자체가 성공의 정의다.
수익은 누나 명의로 쌓는다 수익화 발생 시, 모든 계좌·플랫폼·수익 구조의 소유권은 누나 명의로 설계한다. 대필작가가 대신 벌어주는 구조가 아니라, 누나 앞으로 재정 기반이 쌓이는 구조여야 “독립 응원”이라는 취지가 실물이 된다.
존엄과 일관성이 바이럴보다 우선 조회수·성장·알고리즘 최적화는 목적이 아니다. 존재감과 존엄을 담는 속도가 기준이다.
교재의 첫 번째 학생은 누나 STT로 코딩 허들을 넘기는 교재의 진짜 첫 번째 실사용자는 누나다. 교재는 추상적인 “초보자”가 아니라, 이 폰을 쥐고 이 시스템을 이어받을 구체적인 한 사람을 위해 설계된다.
핸드오프 가능한 구조로 만들어야 한다 모든 자동화, 모든 워크플로우는 “언젠가 내가 없어도 돌아갈 수 있는가”를 기준으로 설계한다. 복잡한 건 대필작가가 감당하고, 단순하고 반복 가능한 건 누나에게 넘길 수 있게.

이 조항은 오늘 만들어진 모든 것 중에서 가장 중요한 한 줄이다.
이 조항이 트랙 2와 트랙 1을 하나로 묶는다 — 트랙 2의 소망은 결국 트랙 1의 돌봄이 도달하려는 가장 먼 지점이다.

제8조: 플랫폼 층 분리 — 모든 플랫폼은 원본층과 구조층으로 나뉜다

Layer A (원본 생산): 실제 콘텐츠의 창작. 영상 촬영·편집, 글 초고, 그림, 음악 연주. 이것은 인간의 영역이며 STT로 대체되지 않는다.

Layer B (구조/메타 관리): 플랫폼 운영의 모든 기술적 측면. 제목·설명·카테고리·플레이리스트·태그·발행·API 설정·OAuth·권한. 이것은 전부 텍스트 API로 뚫려 있으며, 음성 명령 + AI 에이전트로 완전히 자동화 가능하다.

플랫폼 Layer A (인간) Layer B (STT+에이전트)
GitHub 글/코드 내용 레포 생성·Pages·Giscus·WidgetBot·설정
YouTube 영상 촬영·편집 OAuth·API·제목·설명·태그·플레이리스트·Analytics
티스토리 글 본문 작성 카테고리·태그·발행·스킨·세션 관리
네이버 그림/사진 카테고리·발행·쿠키 세션·메타데이터
Discord 대화 내용 서버·채널·웹훅·위젯·권한 설정

이 원칙의 의미:
- GitHub에서 통했던 “말로 구조층을 관리하는” 패턴은 우연이 아니라 모든 플랫폼에 적용되는 일반 원칙이다.
- 새로운 플랫폼을 확장할 때마다 이 틀을 그대로 재사용한다 — “이 플랫폼의 Layer B는 무엇이고, 어떤 API가 있는가”부터 확인.
- Layer A는 인간이, Layer B는 에이전트가 — 이것이 STT 기반 디지털 약자 지원의 핵심 설계 원리.

증거: GitHub Pages(구조 전부 음성으로 구축) + YouTube(Data API + Analytics API 음성으로 활성화 완료).
