# 백서 · 공짜 런타임 플랫폼 생태계로 돌리는 「풀스택 플래너」

## S21 Phone · 5-Repo · 에이전트 3레인

> **명제**  
> 이 레포지토리(및 위성 4종)를 통해, **유료 전용 런타임·비싼 PM SaaS 없이**  
> **프로젝트 · 콘텐츠 · 비즈니스 플래닝**에 필요한 기능을  
> **공짜·저비용 플랫폼 생태계 + 에이전트**로 거의 전부 수행할 수 있다.  
>  
> 플래너는 사람(Boss)이고, **런타임은 플랫폼 조합**이며, **실행 근육은 에이전트 3레인**이다.

---

## 0. 한 페이지 요약 (Executive)

| 항목 | 내용 |
|------|------|
| **무엇을** | 돌봄(트랙1) + 소망/콘텐츠(트랙2) 핸드오프 가능한 생태계 |
| **어디서** | Galaxy S21 · Termux · proot · GitHub · Pages · TG/Discord · (선택) 네이버/유튜브 |
| **얼마에** | 핵심 런타임 **$0 축** + SuperGrok 등 **구독 1개 수준** (토큰 과금 회피 설계) |
| **누가** | 명의·유저 = 누나 / 기획·판단 = Boss / 실행 = cc·ds·gr |
| **어떻게 계획하나** | 레포=스코프, 일지=WBS·결정, 웹진=산출물, 퍼널=비즈, gap check=품질 |
| **결론** | **플래닝 기능 = 별도 툴이 아니라 이 생태계의 운용 방식 자체** |

## 1. 문제 정의

일반 창작자·돌봄 가정·1인 팀은 보통 이렇게 갈린다.

1. **Notion / Asana / Jira** — 계획 툴은 있는데 실행 런타임이 따로  
2. **ChatGPT 구독만** — 말은 되는데 레포·배포·핸드오프가 없음  
3. **클라우드 서버** — 월 비용·운영 부담  
4. **에이전시·PM 외주** — 케어 맥락·명의·속도가 안 맞음  

헬레나 명제는 반대다.

> **버려지는 폰 + 공개 플랫폼 + 저원가 LLM 레인**으로  
> 계획·실행·배포·기록·핸드오프를 **한 줄로** 묶는다.

## 2. 「공짜 런타임 플랫폼 생태계」란

여기서 **런타임** = 코드·문서·봇·페이지가 *실제로 돌아가는 자리*.

### 2.1 계층

```
[판단] Boss
   │
[에이전트 레인]  gr 디자이너 · ds 반장 · cc(감사 예약)
   │
[워크스페이스]   /root/work = helena_phone SSOT
   │
[런타임 $0 축]
   ├─ Termux + proot Ubuntu     ← 로컬 실행
   ├─ GitHub (git/Issues/Actions 선택)
   ├─ GitHub Pages              ← 웹 표면
   ├─ Telegram / Discord        ← 신호·보고
   └─ (선택) RSS·정적 호스팅
   │
[저비용 가속]
   └─ SuperGrok 등 월정액 1레인 (시각·파싱·드래프트)
   │
[유통 표면]
   ├─ Naver 칠판 (유입)
   └─ YouTube (깊이·수익 레이어)
```

### 2.2 “공짜”의 정확한 의미

| 구분 | 설명 |
|------|------|
| **공짜에 가깝다** | Pages, git, Termux, 상당수 API free tier, DeepSeek 경유 코딩 레인 |
| **완전 0원은 아니다** | 폰 전기·데이터, (선택) X/Grok 구독, 도메인 없음(github.io) |
| **비싼 걸 안 산다** | 상시 클라우드 VM, 토큰 무제한 프리미엄 스택, 상용 PM 스위트 필수화 안 함 |

→ **「공짜 런타임」= 월 고정 인프라를 거의 0에 두고, 지능은 구독 1개+오픈 레인으로 때운다.**

## 3. 플래닝 3종을 이 생태계가 어떻게 담당하나

### 3.1 프로젝트 플래닝 → 레포 운용

| 일반 PM 기능 | 이 생태계에서의 구현 |
|--------------|----------------------|
| 비전·원칙 | `CONSTITUTION.md` · 트랙1/2 |
| 스코프 | 5 레포 경계 · “상담소 아님” |
| WBS·산출물 | 커밋 단위 · `99-devlog` · Pages 산출물 |
| 역할 | `_Grok` / `_Aider` / `_Claude` · CLI `gr`/`ds`/`cc` |
| 리스크 | 시크릿 정책 · 돌봄 우선 · 커버리지 가디언 |
| 품질 | Playwright · gap_count · 모바일 거터 |
| 핸드오프 | 명의=누나 · 콜라보 · `g/install.sh` · 방문 세션 |
| 커뮤니케이션 | `tg.sh` · Discord · 일지 |

**도구 비용:** Jira 대신 **git + md + 일지 + TG**.

### 3.2 콘텐츠 플래닝 → 채널·톤·파이프

| 콘텐츠 기능 | 구현 |
|-------------|------|
| 브랜드 라인 | Phone · Log · Faith · Piano · PsyCare |
| 톤·경계 | 각 랜딩 헌장 · 대화록 템플릿 |
| 제작 파이프 | 받음→초안(_Grok)→시공(_Aider)→감사(_Claude)→발행 |
| 유통 | Naver 드래프트 · YT 깊이 · Pages 원본 |
| 아카이브 | `_notebook` → `notebook/*.html` 자동 빌드 |

**도구 비용:** 전용 CMS 대신 **md + build_webzine + 웹진 랜딩**.

### 3.3 비즈니스 플래닝 → 퍼널·원가·거버넌스

| 비즈 기능 | 구현 |
|-----------|------|
| 제품 포트폴리오 | 5 공개 표면 + 문서 IP |
| 유입 | 네이버·웹진·홈 화면 아이콘 |
| 전환·깊이 | YouTube · 교재 · install |
| 원가 | 에이전트 레인 월 구조 (토큰 과금 회피 설계) |
| 거버넌스 | 누나 명의 · 듀얼 폰 · 4중 강제 장치 |
| 지속성 | 방문 설치 = 강제 스프린트 + 초심자 검증 |

**도구 비용:** 피치덱 SaaS 대신 **구조가 피치**.

## 5. 기능 커버리지 매트릭스

| 플래닝 기능 | 커버 | 런타임 요소 |
|-------------|------|-------------|
| 목표·원칙 고정 | ✅ | CONSTITUTION · CLAUDE |
| 작업 분해·추적 | ✅ | git · 99-devlog · 이슈(선택) |
| 역할·위임 | ✅ | 에이전트 마크 · 직함 3종 |
| 문서화 | ✅ | md → HTML 자동 |
| 공개 표면 | ✅ | Pages 5사이트 |
| 콘텐츠 캘린더 골격 | ✅ | 레포별 장르 · 파이프 5단 |
| 비즈니스 퍼널 | ✅ | Naver→YT·Hub |
| 원가 통제 | ✅ | $0 런타임 + 구독 1레인 철학 |
| 품질 게이트 | ✅ | check_webpages · Playwright |
| 이해관계자 신호 | ✅ | TG 보고 |
| 핸드오프·지속 | ✅ | 명의·듀얼·install |
| 재무 모델 숫자 | △ | 구조만 · 1-pager 숫자 보강 여지 |
| 시장 조사 상시 | △ | 리서치 세션성 · 자동화 여지 |
| 실험(A/B) 루프 | △ | 수동 · 향후 캘린더화 |

**판정:** 플래너로서 **필수 기능은 커버**.  
빠진 것은 “플래너 부재”가 아니라 **재무·실험의 명시 레이어**.

## 6. 운영 루프 (플래닝이 도는 방식)

```
1) Boss 방향
2) _Grok 시안·문서·랜딩·비교표·백서
3) _Aider 패치·루프 시공
4) _Claude 감사 (설치 시) / 없으면 Boss 간이 감사
5) git push → Pages 런타임 반영
6) tg.sh 보고 → 사람 확인
7) check_webpages_Grok → gap 0 유지
8) (주기) 누나 폰 설치 = 초심자 검증 = 교재 = 다음 플랜 입력
```

이 루프 자체가 **계획 → 실행 → 배포 → 학습**의 PDCA다.  
별도 PM 툴의 스프린트 보드와 동형이다.

## 7. 비용·제약 · 정직 고지

### 된다
- 계획 문서화, 다중 브랜드 표면, 배포, 알림, 에이전트 분업, 핸드오프 설계  
- 콘텐츠·프로젝트·비즈 **구조 플래닝** 전부  

### 공짜 런타임만으로 한계
- 초저지연 글로벌 서버, 대규모 동시접속 SaaS  
- 법률·의료 책임 대행 (의도적으로 안 함)  
- 구독 0원으로 최상단 멀티모달 무제한 (Grok 등은 선택 투자)  

### 리스크
- 플랫폼 정책 변경 (GH·TG·네이버)  
- 1인 병목 → 듀얼·방문 강제 장치로 완화  
- 문서 과다 → coverage 가디언·아코디언·검색으로 완화

## 9. 결론 · 주장

1. **이 레포 체계 = 공짜(에 가까운) 런타임 플랫폼 생태계**다.  
2. 그 위에서 **프로젝트 · 콘텐츠 · 비즈니스 플래닝 기능을 실제로 수행**하고 있다.  
3. 플래닝은 앱 하나가 아니라 **헌법 + 레포 + 에이전트 + 퍼널 + 보고 루프**의 합이다.  
4. 남은 일은 “플래너 구매”가 아니라 **재무·KPI·실험 루프를 같은 런타임에 한 장씩 더 박는 것**이다.  
5. 돌봄을 깨지 않는 한, 이 모델은 **1인·가족 단위 플랫폼 사업의 최소 실행 가능 플래너**가 된다.
