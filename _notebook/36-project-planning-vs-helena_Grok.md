# 일반 프로젝트 플래닝 vs 헬레나 생태계 플래닝

> 한 줄: 콘텐츠 플래닝으로 시작했지만, **비즈니스 플랜 + PM + 핸드오프 설계**가 같은 레포 구조 안에 이미 겹쳐 있다.  
> 직함은 “PM”이 아니라 **대필작가-간병인 · 시스템 설계**로 적혀 있을 뿐, 하는 일의 집합은 PM·PO·일부 COO에 가깝다.

---

## 1. 한눈에 비교

| 영역 | 일반 프로젝트 플래닝 | 헬레나 (S21 · 5레포) | 대응 여부 |
|------|---------------------|----------------------|-----------|
| **목적 / 비전** | 비전·목표·성공 정의 | 돌봄 깨지지 않게 · 소망 세상에 닿게 · 큰누나 명의 | ✅ 헌법·트랙1/2 |
| **스코프** | In/Out of scope | 5레포 경계, 의료·법률 대행 아님, 행정 대화록 범위 | ✅ |
| **WBS · 산출물** | 산출물 목록·마일스톤 | 랜딩·manifest·docs·수첩·웹진 81p·커버리지 0갭 | ✅ |
| **일정** | 로드맵·스프린트 | 단기간 대량 커밋·일지 §50–74 스프린트성 추진 | ✅ (문서 KPI는 약함) |
| **역할 RACI** | PM/PO/Dev/QA | Grok 디자이너·커버리지 / Aider 반장 / Claude 감사(예정) / Boss 최종 | ✅ |
| **리스크** | 리스크 등록부 | 토큰·개인정보·돌봄 우선·혼자 지속 어려움 | ✅ 구조로 완화 |
| **이해관계자** | 스폰서·유저·팀 | 누나(명의·검증)·Boss(판단)·에이전트(실행) | ✅ |
| **핸드오프** | 인수인계 계획 | 명의=누나, 콜라보, 방문 설치, g/install.sh | ✅ 구조적 |
| **품질** | QA·Definition of Done | Playwright, 모바일 거터, gap check, 아코디언 | ✅ |
| **커뮤니케이션** | 회의·슬랙·주간보고 | Telegram · Discord · 개발일지 · RSS 리마인더 | ✅ |
| **비즈니스 모델** | 수익·원가·채널 | 네이버 유입 → YouTube 깊이, 월 에이전트 원가, 5브랜드 라인 | △ 연결됨·숫자 약함 |
| **시장·페르소나** | TAM·ICP | “복합 돌봄 가정 + 창작 핸드오프” 서사 | △ 암시·미문서 |
| **KPI** | OKR·매출·리텐션 | 발행 리듬·gap_count·설치 성공 암시 | △ 명시 KPI 약함 |

**범례:** ✅ 이미 구조/문서에 있음 · △ 연결은 되나 한 장 사업화 부족

## 2. 콘텐츠 플래닝 ↔ 비즈니스 플래닝

| 콘텐츠 설계 | 비즈니스 대응 |
|-------------|---------------|
| 5레포 = Phone · Log · Faith · Piano · PsyCare | 브랜드 라인업 · 포트폴리오 |
| 네이버 칠판 · 웹진 티저 | 퍼널 입구 (인지·유입) |
| YouTube 강의·연주·기록 | 수익·권위 레이어 |
| GitHub Pages / 수첩 SSOT | IP·운영 매뉴얼·자산 |
| 행정 대화록 · PsyCare 트랙1 | 문제 공간·신뢰 자본 |
| Grok 80% + Aider 시공 | 생산 원가 구조 |
| Paste Pipeline | 발행 SOP (API 없는 채널) |
| 듀얼 폰 · 누나 명의 | 지속성·핸드오프·거버넌스 |

→ **콘텐츠 캘린더만 짠 게 아니라, go-to-market · delivery · continuity 가 같은 설계에 묶여 있다.**

## 3. PM 역할 매핑 (하는 일 기준)

| 일반 PM 일 | 헬레나에서 실제로 한 일 |
|------------|-------------------------|
| 스코프 고정 | 트랙1/2, 레포 정체성, “상담소 아님” 경계 |
| WBS | 위성 랜딩·아이콘·docs·웹진 빌드 파이프 |
| 일정 추진 | 4일 전후 대량 산출·일지 바텀업 |
| 역할 배분 | cc/ds/gr + 직함 3종 |
| 리스크 관리 | 돌봄 우선, 시크릿, 커버리지 가디언 |
| 이해관계자 | 누나 환경=테스트+미래 운영 |
| 품질 게이트 | 모바일·아코디언·Playwright |
| 종료/이관 | 명의·콜라보·방문 강제 설치 4중 장치 |

**한 줄:** Boss(+에이전트) = **콘텐츠 PM + 프로덕트 오너 + 일부 운영(COO) 스캐폴드**.

## 4. 일반 플랜과 다른 점 (차별 · 의도)

| 일반 프로젝트 | 헬레나 |
|---------------|--------|
| 산출물 납품이 끝인 경우 많음 | **핸드오프가 목표** (명의·폰·교재) |
| 감성은 부록 | **감성 → 구조 번역** (계정·방문·install) |
| PM 문서가 중심 | **레포·사이트가 살아있는 플랜** |
| 팀 채용 전제 | **에이전트 3레인 + 월 고정비** |
| 실패 = 일정 지연 | 실패 = 돌봄 깨짐 → 트랙1 절대 기준 |

---

## 5. 아직 비는 칸 (명시 사업계획 기준)

1. 수익 모델 1순위와 월 숫자 가정  
2. 페르소나·시장 한 단락  
3. 3/6/12개월 KPI (발행·설치·핸드오프)  
4. 수익 귀속·세무 절차 (철학은 명의에 있음)  
5. 공식 “중단/축소” 조건  

→ **연결은 됐고, 1-pager 사업계획 문장만 안 뽑힌 상태.**
